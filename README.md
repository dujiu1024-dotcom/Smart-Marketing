## 多文件 Demo
入口：`demo/index.html`

文件结构：
- `demo/index.html`：应用入口
- `demo/styles.css`：设计系统与响应式样式
- `demo/data.js`：演示种子数据（含明确标记的热点机会样例）
- `demo/store.js`：本地状态与持久化
- `demo/app.js`：门店端页面、路由、营销流程与交互
- `demo/admin.js`：平台管理端页面与操作

## 本地运行
ES Module 需要通过 HTTP 服务运行，不建议直接双击 HTML 文件。

在仓库根目录执行：

```bash
python -m http.server 8080
```

浏览器访问：

```text
http://localhost:8080/demo/
```

## Demo 交互范围
- 门店端：AI 营销、热点机会工作台、七步营销任务工作区、账号运营监测、经营效果、独立门店资料工作区。作品登记需关联任务与冻结内容包，官方数据 API 未接入时不展示假指标。
- 经营效果：独立模块，包含内容表现、账号运营监测和经营指标；默认无真实数据时显示空状态/接入指引，演示样例必须明确标记。
- 门店经营资料由门店端维护：门店档案、商品与服务、活动与优惠、品牌规范、客群与经营、知识库、素材库、渠道账号；平台管理端只管理门店用户和门店级模型配置。
- 平台管理端：运营总览、门店列表 → 门店详情、AI 运行监控（任务列表 → 单任务详情）、AI 能力配置（按业态可编辑提示词模板）、用量与成本、审计日志和可编辑系统配置。
- 状态与记录保存在当前浏览器 localStorage；当前任务定位可刷新恢复，旧数据读取时执行字段迁移。单文件上传限制 1 MB，并在上传前检查本地存储余量。

## 真实服务边界
当前版本是前端产品交互原型：
- AI 文案生成/整改使用模拟逻辑。
- 图片生成/二次改造使用模拟适配器，展示本地 SVG 示意预览，不是真实图像模型结果。
- 渠道 OAuth、草稿保存、真实发布未连接。
- 真实热点采集、平台表现数据及经营效果数据服务尚未连接；当前未确认 POS、团购核销、CRM、会员等系统接入。
- 管理端不具备生产环境身份认证、服务端门店级访问控制、密钥托管和防篡改审计；未接入的安全/能力开关为禁用状态。

演示数据现覆盖 7 家不同业态门店、门店专属商品与活动、13 个营销任务、热点机会、效果报告和 AI 节点运行记录。所有模拟能力均应按演示状态理解，不代表真实服务已经接通。

## 产品范围纠偏（2026-11-10）

- 热点采集与门店匹配是 AI 营销核心能力：当前 Demo 已提供热点机会工作台、演示匹配理由和采纳创建任务链路；真实热点采集、动态匹配、去重和来源链接仍未接入。
- 门店是管理主体；用户管理位于门店详情；模型与 API Key 按门店绑定。
- 不建设租户管理、角色管理、工单、后台素材审核、后台渠道/数据接入中心或独立归因后台。
- 任务监控与 AI 运行记录合并为 AI 运行监控，按营销任务查看业务进度并下钻 AI 调用。
- 具体修订以产品设计 v1.7、UI/UX 审查和验收矩阵 v1.5 为准。第三轮 P0-P2 修复状态及未验证边界已追加至验收矩阵。

## 产品范围基线 v1.8（2026-11-10）

- 定位：AI 门店运营官；按需制作，AI 完整执行营销，核心壁垒是可验证的经营效果。
- 首页“AI 推荐营销”直达发现营销机会；同时保留自然语言按需制作。
- 营销链路：需求理解 → 机会发现 → 策略确认 → 文案生产/审核 → 图片生产/审核 → 渠道适配 → 质检 → 发布确认。
- 营销任务只管理执行、审核、发布状态和异常；不重复设置新建入口，也不在任务完成时自动复盘。
- 经营效果独立于任务，包含内容表现、账号运营监测和经营指标。
- 本店发布内容通过平台发布记录/平台内容 ID、官方授权账号作品匹配或商家人工确认关联识别；不能凭相似度推断。
- 优先官方授权 API；接口不可用时人工粘贴链接/导入；数据必须标注来源、更新时间、口径和可信度。
- 不做广告投放预算、ERP、POS、CRM、会员、租户、独立角色、工单和独立归因后台。
- Demo 必须有完整页面和真实交互；模拟服务与真实生产能力严格区分。
