# Issue #12 首个渠道候选平台核验（2026-11-11）

> 状态：公开官方文档初筛；尚未取得本项目应用资质、平台审核结果或真实账号测试证据。  
> 结论用途：供项目负责人选择试点平台；不能据此宣称已接通。

## 1. 选择门禁

Issue #12 要求先验证真实 OAuth、账号能力、草稿/读回或经批准的替代路径、发布与外部状态核验。平台必须由项目负责人确认；本报告不替负责人锁定平台。

评估项：
- 官方 OAuth 与服务端 API 的可用性、申请门槛和所需主体资质。
- 用户授权 Scope、账号信息读取和 Token 刷新/撤销。
- 草稿创建与读回；若无草稿能力，是否有经产品批准的“商家明确确认后直接发布”替代路径。
- 发布 API、外部 ID、作品 URL、状态查询/Webhook 和重复请求语义。
- 测试账号、地区、审核周期、速率限制、内容限制、数据处理条款。

## 2. 官方资料初筛

### 抖音

已核实：
- 官方开放平台存在“创建视频”接口，要求申请对应权限并取得用户授权；接口创建后可能经历审核，审核期间仅自己可见。
- 官方资料说明代用户创建内容时，产品必须让用户明确感知每次操作，否则可能回收接口权限。
- 官方资料也列出 H5/APP 场景的“发布内容至抖音”能力，属于需申请能力的分享/投稿流程。

未核实：
- 是否向本项目类型/主体开放所需 Scope；能否获得测试应用和可用账号。
- 是否存在适合本产品的草稿创建与读回 API；目前检索到的创建视频能力不能直接等同草稿保存。
- 账号级作品查询、Webhook、失败/重复请求处理的完整可用范围。

初步判断：**值得优先申请核验**，但需确认网站应用/H5投稿场景是否满足桌面 Web 工作流；不可先把发布接口当作草稿接口。

官方资料：
- https://partner.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/create-video/video-create
- https://partner.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/create-video/upload-video
- https://developer.open-douyin.com/capacity-center-page/capacity-detail/7180322911280955447

### 快手

已核实：
- 官方文档公开 OAuth scope `user_video_publish`。
- 发布流程包括发起上传、上传视频、调用发布接口；发布响应包含 photo_id 等作品信息。
- 官方明确发布为异步过程，接口响应不代表作品已出现在用户主页；可用查询视频 API 根据 photo_id 核验最终状态。

未核实：
- 应用注册和权限审核是否适用于本项目主体/行业。
- 是否有草稿 API/草稿箱读回；当前公开发布流程是直接发布流程，不应冒充草稿保存。
- 测试账号和可用 API 权限是否能及时取得。

初步判断：**服务器端发布与结果核验路径相对清晰**，但目前缺少已证实的草稿能力。若选择快手，需要产品负责人书面批准“商家确认后直接发布、以平台查询结果核验”的替代验收路径，或先证明存在官方草稿接口。

官方资料：
- https://open.kuaishou.com/platform/openApi?group=GROUP_OPEN_PLATFORM&menu=20
- https://open.kuaishou.com/platformDocs/openAbility/contentManagement/createAVideo

### 小红书

已核实：
- 小红书开放平台当前快速接入文档说明首期只开放用户基本信息 `basic_info` 授权范围。
- 小红书分享开放平台页面当前标注“暂停接入”；不能将分享能力视为当前可申请。
- 开放账号 API 资料列出 OAuth/用户基本信息能力，但没有在已检索的当前文档中确认服务端笔记草稿、发布与读回接口。

初步判断：**当前不建议作为首个官方 API 试点**，除非项目主体已经获得额外商业合作或特定发布能力的正式授权证明。

官方资料：

- https://openaccount.xiaohongshu.com/docs/api-reference
- https://agora.xiaohongshu.com/

## 4. 建议决策

建议先向**抖音与快手**同时核实应用资质和测试权限，再根据以下硬门槛选择唯一首个平台：
1. 本项目实际主体能注册并通过应用审核。
2. 能拿到 OAuth、账号身份及目标发布 Scope。
3. 能完成商家明确感知的内容交付动作。
4. 能取得外部作品 ID，并有官方查询 API 或等效可靠证据核验结果。
5. 草稿能力若不存在，产品负责人必须明确批准替代路径；未经批准不得把“直接发布”视为满足草稿验收。
6. 能提供真实测试账号与非生产测试方案。

**目前不能直接开始某一平台的真实 SDK/发布实现。** 可以并行完成与平台无关的 ChannelAdapter、能力快照、OAuth 安全存储和 PublishOperation 测试骨架，但这些仍须等待 #5/#8/#9/#10 对应生产接口达到可联调状态。
