# Frozen Demo 路由与页面状态映射

> 基线：main 分支 `demo/` 当前 Demo（产品基线 v1.8）
> 用途：Issue #4 开发前对照和浏览器验收导航；本文件不代表这些页面已由生产 Web 应用实现。

## 1. 路由机制

Demo 使用 `location.hash` 作为页面路由；`demo/app.js` 监听 `hashchange` 并重新渲染。当前任务 ID 另存于 localStorage（`ai-store-ops-current-task`），门店与平台管理演示数据由 `demo/store.js` 持久化。刷新页面应恢复当前 hash 对应页面；任务详情应恢复有效任务选择。

路由是 Demo 原型路由，不等同于生产 API 路由。未知路由回退到 AI 营销首页；无效任务/热点 ID 应呈现可返回的空态或详情失效提示。

## 2. 门店工作台一级导航

| Hash | 页面 | 页面职责 | 关键状态/交互 |
|---|---|---|---|
| `#ai` | AI 营销 | 首页；AI 推荐营销机会与按需制作入口 | 显示当前门店任务摘要；热点标注为演示样例 |
| `#tasks` | 营销任务 | 当前门店任务列表 | 搜索、状态/类型筛选、打开任务 |
| `#effects` | 经营效果 | 独立效果分析与报告 | 时间窗口、任务筛选；演示数据必须显式标记 |
| `#account-ops` | 账号运营监测 | 渠道账号状态、作品登记与归属核验 | 登记作品入口；未核验作品不得计入正式归因 |
| `#store:profile` | 门店资料 | 门店经营资料工作区 | 进入八个门店资料分类 |

## 3. AI 营销与任务二级页面

| Hash | 页面 | 入口/状态 |
|---|---|---|
| `#create` | 按需制作 | AI 营销首页的按需制作入口；提交前核对目标、商品、客群、活动和渠道 |
| `#hotspots` | 发现营销机会 | AI 营销首页的推荐入口；支持搜索、分类/状态筛选 |
| `#hotspot-detail:<hotspotId>` | 热点机会详情 | 从机会卡片进入；支持采纳、忽略、暂缓；过期机会不可采纳 |
| `#task` | 营销任务工作区 | 从任务列表打开；当前任务 ID 单独持久化 |
| `#account-register` | 登记已发布作品 | 从账号运营监测进入；要求关联已冻结发布包、渠道和作品链接 |

### 营销任务工作区的七个内部 Tab

这些是同一任务工作区内的状态页签，不是独立 hash 路由。Tab 选择保存在当前页面内存状态，刷新后默认回到需求理解。

| Tab key | 页面 | 主要门槛/状态 |
|---|---|---|
| `brief` | 需求理解 | 商家核对目标、商品、客群、活动事实并确认 |
| `strategy` | 策略确认 | 需求确认后可编辑；热点决策必须明确，跳过需填写原因 |
| `copy` | 文案工作室 | 按渠道独立编辑、整改、版本留存与审核 |
| `image` | 图片工作室 | 原图改造/生成/上传；独立版本和审核状态 |
| `channel` | 渠道适配 | 本地预览与字段检查；不代表真实 OAuth 或发布规范 |
| `quality` | 质量检查 | 对当前内容版本执行规则质检；输入变化使旧质检失效 |
| `publish` | 发布确认 | 需求、热点、策略、各渠道文案、图片、质检和商家最终确认全部满足后冻结发布包；不执行真实平台发布 |

任务 Tab 使用 `role=tab`、`aria-selected` 和 `tabpanel`；支持方向键、Home、End 键盘切换。

## 4. 门店资料工作区

统一入口 `#store:<section>`，八个分类由页面内 Tab 切换，并同步 hash：

| Section | 页面 | 主要职责 |
|---|---|---|
| `profile` | 门店档案 | 主体、地址、联系人、营业时间、服务与经营基础信息 |
| `products` | 商品与服务 | 商品/服务事实、价格、规格、供应、确认状态 |
| `offers` | 活动与优惠 | 优惠机制、适用商品、期限、限制和确认状态 |
| `brand` | 品牌规范 | 品牌视觉、语气、定位、差异化和禁用承诺 |
| `audience` | 客群与经营 | 客群、消费场景、经营目标、时段和产能约束 |
| `knowledge` | 门店知识库 | SOP、FAQ、品牌故事、活动规则等知识资料 |
| `assets` | 素材资产库 | 原始素材、来源、版权和商品关联 |
| `channels` | 渠道账号 | 平台账号、授权范围、能力和连接状态（演示连接） |

商品与活动编辑是独立二级页面，分别使用 `#store-editor:product:<id|new>` 与 `#store-editor:offer:<id|new>`。知识、素材等轻量编辑沿用模态表单，不应误改为商品/活动编辑路由。

## 5. 平台管理工作区

平台管理入口由顶部“平台管理端”切换进入；一级页面统一使用 `#admin:<page>`。

| Hash | 页面 | 二级状态/说明 |
|---|---|---|
| `#admin:overview` | 运营总览 | 平台状态与能力摘要；演示指标须明确标注 |
| `#admin:stores` | 门店管理 | 门店列表；进入门店详情 |
| `#admin:monitoring` | AI 运行监控 | 任务运行列表；进入单任务运行详情 |
| `#admin:capabilities` | AI 能力配置（导航标签）；页面标题为“AI 能力与提示词配置” | 业态与提示词模板列表；进入提示词独立编辑页 |
| `#admin:costs` | 用量与成本 | 展示调用样例；真实账单未接入 |
| `#admin:audit` | 审计日志 | 平台管理操作记录 |
| `#admin:settings` | 系统配置 | 平台名称、默认时区、保留周期和业态分类 |
| `#admin:store-detail` | 门店详情 | 从门店列表进入；内部 Tab：门店用户、模型配置 |
| `#admin:monitor-detail` | 运行详情 | 从运行列表进入；任务事件与 AI 节点明细 |
| `#admin:prompt-detail` | 提示词编辑 | 从能力配置进入；保存创建新版本，不覆盖旧版本 |

平台管理的门店用户管理、模型配置和提示词编辑均属于管理端二级状态；不能把它们与门店端经营资料维护混为同一职责。

## 6. 生产实现映射边界

- 本映射冻结 Demo 页面/路由/状态名称，不授权改变现有 IA、导航或流程。
- 生产 Web 应按页面职责映射到真实路由/页面组件；路由路径可按技术规范设计，但必须保留本表对应关系、页面层级和交互预期。
- 生产 API、认证、门店授权、Job Runtime、真实 AI Provider、OAuth、发布和经营数据采集仍由各自 Issue 实施；Demo 的 localStorage 状态不能作为生产持久化或授权实现。
- Demo 的“模拟适配器/演示数据”必须保留明确边界，不能在生产界面伪装为真实能力。

## 7. 浏览器验收覆盖

PR #16 的 `apps/e2e/demo_smoke.py` 对上述导航和二级页面执行 Chromium 冒烟：一级路由、八个门店资料 Tab、七个任务 Tab、平台管理页面、门店详情/运行详情/提示词编辑、商品/活动编辑页以及浏览器历史导航。它只证明路由与页面壳可访问，不替代 `docs/DEMO_ACCEPTANCE_MATRIX.md` 中的完整业务流程、字段、异常、响应式、可访问性和生产服务验收。


## 8. 首个生产 Web 页面映射（2026-11-12）

- Demo 的 `#store:profile` 门店档案页面已开始生产接入，首个页面位于当前 React 门店工作台入口。
- 真实数据源为 `GET/POST/PATCH /api/v1/store/profile`；所有请求携带当前 `X-Store-ID`，写请求携带 CSRF Token；更新使用 `If-Match` 版本。
- 页面包含登录、当前用户 Session 恢复、门店选择、门店档案创建/编辑、营业时间/服务能力/临时停业字段和显式事实确认。
- 其他 Demo 路由、七个门店资料分类、营销任务和平台管理页面尚未由生产 Web 实现。导航对未接入模块明确禁用/标记，不将 Demo 的 localStorage 作为生产数据。


## 9. 商品与服务生产路由映射（2026-11-12）

- `#store:products` 对应商品与服务生产清单，数据来自门店范围 GET `/api/v1/store/products`。
- `#store-editor:product:new` 与 `#store-editor:product:<id>` 对应独立商品编辑二级页面；保存通过 POST/PATCH `/api/v1/store/products`，更新使用 If-Match 当前版本。
- 商品事实确认使用 POST `/api/v1/store/products/<id>/confirm-facts`，绑定精确版本；未保存修改时不允许确认。
- 商品删除使用 DELETE `/api/v1/store/products/<id>` 与 If-Match，后端保留审计历史。
- 其余七个门店资料分类仍待接入，不因商品页面完成而改变 Demo 信息架构。
