# AI 门店运营官 — 现有 Demo 深度 UI/UX 审核与重构清单

审查基线更新（2026-11-10）：当前 `main` 已采用 `demo/` 多文件应用，产品设计基线为 v1.5。本文前半部分保留的是重构前历史审查，不代表当前页面现状；当前缺陷、修复状态与验收边界以 `DEMO_ACCEPTANCE_MATRIX.md` 最新版本为准。

## 一、总体结论

| 维度 | 现状与问题 | 重构要求 |
|---|---|---|
| 信息架构 | 首页、任务、效果、门店资料、管理端混在单页 | 门店端 AI 营销/任务/经营效果/资料中心；管理端独立导航 |
| 视觉设计 | 通用卡片和表单拼接，层级、密度、焦点不足 | 统一设计系统、响应式布局、工作台式操作 |
| 任务体验 | 任务列表与工作区弱耦合，缺少详情状态时间线 | 任务列表、任务详情、审核队列、执行记录分层 |
| 文案审核 | 仅有简单编辑和审核按钮 | 平台独立版本、标题/正文/话题字段、差异比较、选区整改 |
| 图片工作室 | 有模式概念，但素材/画布/源图关系不完整 | 素材库、双模式、画布对比、参数、版本和源图追溯 |
| 渠道适配 | 少量渠道 tab | 独立字段、规格校验、预览、质检和状态 |
| 发布 | 模拟发布按钮 | 授权、能力、时间、回执、失败、幂等 |
| 经营效果 | 被放在任务完成链路 | 独立效果中心，按观察窗口和真实数据分析 |
| 门店资料 | 名称、行业、地址、少量商品/知识 | 完整门店、商品、活动、品牌、客群、知识、素材、渠道和数据连接 |
| 管理后台 | 单一管理面板/模型配置示意 | 租户、用户权限、任务监控、模型、提示词、连接器、计费、工单、审计 |
| 数据与状态 | 单对象、单页脚本、状态扁平 | 领域模型、独立状态、事件记录、持久化 |
| 工程结构 | 单个 index.html 内联 CSS/JS | 多文件模块化、适配器分层 |

## 二、现有页面逐页审查

### 1. 首页 / AI 营销入口
现有输入框、任务统计和建议任务入口不足以支撑营销工作台。缺少任务类型、目标商品/服务、客群、活动时间、预算、渠道、期望动作、素材和补充说明等结构化输入；缺少 AI 理解确认、经营上下文证据、事实冲突和缺失信息追问。重构为“自然语言输入 + AI 结构化理解 + 经营依据 + 策略确认”的工作台，首页只显示执行待办，不显示虚构效果结论。

### 2. 营销任务列表
缺少任务类型、商品/门店、渠道、负责人、创建/更新时间、当前阻塞节点等字段；筛选、排序、分组、分页、批量归档、复制和恢复能力不足。任务详情缺少版本链、审核历史、执行事件和失败恢复上下文。重构列表字段：目标摘要、类型、执行状态、文案审核、图片审核、渠道/发布状态、更新时间；详情展示执行时间线和工作区，不放效果复盘。

### 3. 策略确认
策略没有完整结构：目标指标、客群、场景、商品依据、卖点、主题、渠道理由、活动机制、素材清单、风险和衡量方式缺失；事实来源、确认状态、置信度和证据未展示；重生成、版本比较和回滚不足。重构为结构化策略工作区，区分商家事实、外部证据和 AI 推断，关键事实需确认。

### 4. 文案工作室 / 审核
多渠道版本缺少独立字段模型；标题、正文、话题没有分开编辑；段落定位、选区修改、版本 diff、撤销/恢复不足；上传解析、来源、审核人、审核时间和审核对象版本元数据不全。重构为平台独立文案版本，审核绑定具体版本 ID；上传作为新版本，必须重新审核。

### 5. 图片工作室 / 审核
缺少素材库选择、格式/尺寸/版权信息、画幅/版式/品牌色/字体/文字层级参数、源图与结果对比、源图 ID 和生成参数；单张/图片组审核粒度不清；上传自有图片的替换/参考/采用语义不完整。重构为左侧素材栏、中间画布与对比、右侧生成参数；明确“直接生成信息图”和“商家原图二次改造”；源图只读，衍生资产保留来源。

### 6. 多平台适配 / 最终确认
各平台独立标题、正文/脚本、话题、封面、素材、字数/尺寸校验不足；账号授权和发布能力未绑定；缺少质检阻断、预约时间、平台回执、失败原因、重试和幂等。重构为渠道适配矩阵 + 单渠道详情 + 发布中心；不支持自动发布时明确转人工操作。

### 7. 经营效果
把效果入口放进任务完成流程，时间逻辑不成立：刚发布不会立即有足够数据。指标缺少来源、周期、更新时间、口径和归因可信度；内容表现、意向、到店交易、ROI 未分层。重构为独立一级模块，支持 24 小时/7 天/30 天/自定义观察窗口；未达到窗口显示观察中，无数据源显示接入指引，不填充虚构数值。

### 8. 门店资料
当前基础资料、少量商品、知识文本和素材上传明显不足。缺少：
- 门店身份、品牌/连锁、编码、行业、地址、坐标、电话、联系人、营业时间、节假日、服务范围、门店能力。
- 商品 SKU/规格/单位/价格/状态/库存产能/卖点/成分/过敏原/服务流程/交付方式/素材授权。
- 活动优惠规则、适用范围、门槛、叠加、有效期、核销和审批。
- 品牌 Logo/色彩/字体/视觉风格/品牌故事/语气/禁用词/CTA。
- 客群、消费场景、购买动机、经营目标、淡旺季、产能限制。
- 知识库类型、来源、版本、负责人、可见范围、生效失效日期、审核状态。
- 素材尺寸、格式、时长、标签、商品/活动关联、版权/肖像授权和审核状态。
- 渠道账号授权、POS/订单/CRM/会员/优惠券/广告数据连接。
重构为分区资料中心，字段支持来源、确认状态、更新时间和完整度提示。

### 9. 管理后台
当前后台不是可用管理系统。缺少租户/门店生命周期、用户/角色/权限矩阵、任务节点监控、耗时/重试/取消/失败堆栈脱敏、模型供应商和能力路由、密钥引用、超时/并发/降级/健康检查、提示词版本、工作流节点、能力开关、素材审核、渠道适配器、数据同步、归因、成本账单、告警、异常工单和审计日志。重构为独立运营后台，模块可筛选、查看详情、执行操作并留下审计记录。

## 五、统一 UI/UX 规范

- 主导航与辅助设置明确分层，避免把资料设置与高频营销动作混排。
- 列表具备搜索、筛选、排序、分页/合理分组、空状态和批量操作。
- 详情页具备标题、状态、关键操作、主体数据和历史记录。
- 所有字段有标签、说明、必填规则、格式校验、错误提示和保存状态。
- 每个按钮必须产生业务状态变化、导航、数据更新或明确的未连接提示。
- 任务状态、审核状态、发布状态、数据状态分离。
- 高风险操作二次确认并记录审计事件。
- 桌面、平板、手机均可用；移动端复杂表格降级为详情卡。
- 无真实数据时不伪造经营效果；观察窗口未到时显示观察中。
- AI 和第三方服务未连接时显示模拟适配器，不得伪装真实生成或发布成功。

## 六、重构实施顺序

1. 页面地图、字段字典、状态机与角色权限矩阵。
2. 多文件工程结构、设计系统、路由和独立数据模型。
3. 门店端核心营销闭环和任务管理。
4. 独立经营效果中心与数据来源门槛。
5. 完整门店资料中心。
6. 完整平台管理后台。
7. 页面字段覆盖、关键路径交互、刷新持久化和响应式测试。
8. 对照产品设计逐条验收；未实现项列为缺口，不宣称与正式系统一致。

## 七、验收红线

- 营销任务不嵌入即时效果复盘。
- 无真实采集数据时不展示真实经营效果数值。
- 未审核文案/图片不得进入发布包。
- 原图不得被改造结果覆盖。
- 每个任务、渠道版本、审核对象必须独立状态。
- 管理后台不能只有一个运营总览示意页。
- 不允许无响应按钮、假保存、假删除、假发布或无反馈上传。
- 门店资料字段足以支持 AI 决策、内容生成、事实校验和渠道发布。


## 八、2026-11-10 二次代码审查补充

### 已核实并修复
- 商品新增/编辑不得在保存时自动置为已确认；需由商家在商品列表显式确认，且商品名称、SKU、有效售价必须满足基本条件。
- localStorage 写入失败时恢复最近一次成功持久化快照，避免继续把失败写入当作已保存数据。
- 统一补齐门店、商品、活动、知识、素材、渠道、数据源、效果与管理端集合；通过 schemaVersion 标记当前数据结构版本。
- 种子源素材增加明确标注的 SVG 演示预览；图片整改继承原画幅，并根据风格/指令变化模拟预览。

### 审查中排除的误报
- 管理端新增数据连接表单实际提交动作是 `save-data`，应用提交处理器存在对应分支并写入 `dataSources`；此前将其判定为“保存分支缺失”不准确。本次保留该功能并纳入回归测试。
- 上述源素材 SVG 仅为原型占位视觉，不是真实门店照片或图像模型编辑结果。

### 仍需浏览器验收
- 商品新增/编辑后待确认、显式确认、未确认商品质检阻断。
- 存储配额异常时状态回滚和用户反馈。
- 管理端数据连接新增、刷新后保留。
- 图片源图/结果并排预览、画幅继承、整改参数变化和版本恢复。
- 旧版本 localStorage 数据迁移、窄屏布局及文件上传流程。
